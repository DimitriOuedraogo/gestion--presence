1 Vue d'ensemble du projet

Gestion Présence est une application web développée avec Laravel 12 permettant à une organisation de gérer les présences de ses agents lors de sessions de formation ou de réunions. Le système repose sur la génération de QR codes uniques par session : les agents scannent le QR code avec leur smartphone et renseignent leur email pour marquer leur présence.

👤 Côté Administrateur

  • Connexion sécurisée par mot de passe
  • Gestion des sessions de présence
  • Gestion des points de présence (lieux)
  • Génération et affichage des QR codes
  • Consultation des présences par session
  • Export Excel des listes de présence
  • Consultation de la liste des agents

📱 Côté Agent (Public)

  • Scan du QR code de la session
  • Saisie de l'email professionnel
  • Vérification automatique de l'identité
  • Confirmation de présence instantanée
  • Accès uniquement pendant la plage horaire
  • Pas de compte requis

Méthode clé : SessionPresence::estActive()

Cette méthode détermine si une session est actuellement en cours en comparant l'heure actuelle avec la plage horaire définie :

public function estActive(): bool
{
    $now   = Carbon::now();
    $debut = Carbon::parse($this->date_presence . ' ' . $this->heure_debut);
    $fin   = Carbon::parse($this->date_presence . ' ' . $this->heure_fin);
    return $now->between($debut, $fin);
}

6 Authentification administrateur

L'accès à l'interface d'administration est protégé par un système d'authentification par mot de passe simple, basé sur les sessions Laravel.

Fonctionnement

  • Page de login : /admin/login
  • Mot de passe vérifié contre ADMIN_PASSWORD dans le .env
  • Session créée : admin_logged_in = true
  • Middleware AdminAuthenticated sur toutes les routes /admin/*
  • Déconnexion via bouton dans la sidebar

Configuration

Le mot de passe est défini dans le fichier .env :

ADMIN_PASSWORD=1234567890

⚠️ Changer ce mot de passe en production.

7 Gestion des sessions de présence

Une session de présence représente un événement (réunion, formation, etc.) pour lequel on souhaite enregistrer les participants. Elle est associée à un point de présence (lieu) et définie par une plage horaire.

Cycle de vie d'une session

Création → Génération Token UUID + QR Code SVG → Session active (pendant la plage horaire) → Agents marquent leur présence → Session expirée → Consultation / Export

Attributs formatés (Accessors)

AttributRetourExemple
datePresenceFormateeDate en format français18/06/2026
heureDebutFormateeHeure début HH:MM08:30
heureFinFormateeHeure fin HH:MM17:00

Points de présence (lieux)

Chaque session est liée à un point de présence qui représente le lieu physique. Les coordonnées GPS (latitude/longitude) sont détectées automatiquement via l'API navigator.geolocation lors de la création dans le formulaire admin.

8 Système QR Code

À la création de chaque session, un QR code unique est automatiquement généré au format SVG et stocké dans storage/app/public/qrcodes/.

Génération

// URL construite depuis APP_URL (indépendant de l'IP de connexion admin)
$url = rtrim(config('app.url'), '/') . '/presence/' . $session->token;

// Génération SVG 300x300px
$svg = QrCode::format('svg')->size(300)->margin(1)->generate($url);
Storage::disk('public')->put('qrcodes/session_' . $session->id . '.svg', $svg);

Points importants

  • Le token est un UUID v4 unique et non devinable
  • L'URL dans le QR code utilise APP_URL du .env (pas l'IP de connexion admin)
  • Le bouton "Régénérer QR" permet de mettre à jour tous les QR codes si l'URL change (changement d'IP réseau)
  • Les QR codes sont servis publiquement via storage/qrcodes/session_X.svg

Configuration APP_URL selon le réseau

ContexteAPP_URL à utiliser
Test local (PC uniquement)http://127.0.0.1:8000
Réseau WiFi local (téléphone sur même réseau)http://<IP_WIFI_PC>:8000 (ex: 172.16.0.96)
Tunnel public (ngrok, etc.)https://xxxx.ngrok-free.app

10 Système anti-fraude

Deux mécanismes de contrôle sont en place pour éviter les présences frauduleuses :

🚫 Règle 1 — Un email par session

Un agent ne peut marquer sa présence qu'une seule fois par session. Si l'email a déjà été utilisé pour cette session, la demande est rejetée.

Presence::where('session_presence_id', $id)
  ->where('agent_id', $agent->id)
  ->exists();

⚠️ Règle 2 — Une IP par agent

Si une adresse IP a déjà été utilisée par un autre agent dans la même session, une alerte est levée (possible partage de dispositif frauduleux).

Presence::where('session_presence_id', $id)
  ->where('adresse_ip', $ip)
  ->where('agent_id', '!=', $agent->id)
  ->exists();

# 1. Nettoyer les caches
php artisan config:clear
php artisan cache:clear
php artisan view:clear
php artisan route:clear

# 2. Compiler les assets CSS/JS
npm run build

# 3. Lancer le serveur (accessible depuis le réseau local)
php artisan serve --host=0.0.0.0 --port=8000

# 4. Si XAMPP MariaDB n'est pas lancé (Windows)
C:\xampp\mysql\bin\mysqld.exe --defaults-file="C:\xampp\mysql\bin\my.ini" --standalone

⚠️ Note importante — Réseau WiFi

Pour que les agents puissent scanner le QR code depuis leur téléphone, le PC et les téléphones doivent être sur le même réseau WiFi. En cas de changement d'IP (reconnexion WiFi), il faut :

  • Mettre à jour APP_URL dans le .env avec la nouvelle IP
  • Relancer le serveur
  • Cliquer sur "Régénérer QR" dans l'admin pour mettre à jour les QR codes

Lien symbolique storage
